# Adversarial UX review — September 23, 2026

This records the original review and its then-current resolutions. Issue #43
subsequently removed the local inquiry draft, global preview notice and
unapproved Private Equity eight-hour target; see [current validation](../VALIDATION.md).

An adversarial UX test of the deployed preview
(`https://nicolas-found42.github.io/website-redesign/`, `02607f6`). The persona
was a 62-year-old private-equity operating partner, a skeptical buyer who
wanted to learn in a minute what Found42 does, whether it has done this for PE,
what it costs, and how to get a call. A pragmatism filter then separated real
UX problems from persona noise. The RED and GREEN findings became issues
#32–#40 and the YELLOW ones the catch-all #41, each with the screenshots taken
on the deployed site. `tests/ux-review.spec.ts` names each test for the issue
it guards.

### #41 items

- **Discuss buttons dropped the service.** Fixed: the dialog reads "About Workflows" and the copied message leads with the service.
- **`name@gmail` accepted.** Fixed: email fields require a dot in the domain.
- **Reading times on unwritten essays.** Fixed: they are withheld until an essay has an `href`. The manifest records them as `withheld`, and the coverage test asserts they are absent.
- **Services repeated the homepage first.** Fixed by #39: the engagement band now opens the page.
- **The PE hero stat undercut itself.** Fixed: the opening leads with a workflow, and the 8h target keeps its qualification lower on the page.
- **The hero's only primary CTA is free resources.** Unchanged by decision. The 16 September meeting resolved "three competing hero actions" into one (`docs/MEETING-COVERAGE.md`), and the sticky header's "Talk to us" is always visible. A second hero action would reopen that decision, so it needs the team rather than a UX ticket.
- **A "Scorecard" that "is not a score".** Fixed: the intro says what the result is. The product name is unchanged.
- **The newsletter placeholder was truncated.** Fixed: the aside's email field stacks above its action.

Blog stays in the primary navigation. Its route is in the source registry, and
its newsletter signup is why it exists.
